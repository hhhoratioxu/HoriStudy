# HoriStudy 0.2.0 Preview 3 验证记录

记录日期：2026-10-17，Asia/Taipei。

## 当前结论

新版已完成 arm64 与 x86_64 编译及本地临时签名。答案规则、错误分类、模拟多供应商 API 传输、网页回答格式、生产网页登录工作台、本地登录回调、自建课程页面及生成的视频夹具共 **130 项检查通过**。

**四家真实账号的订阅登录和完整网页作答尚未验收。真实学生账号登录也尚待用户重试确认，真实作业、考试和课程进度均未验收。** 本地登录回调通过不能证明真实网站登录成功；模拟 API、架构构建或界面截图不能作为真实答题准确率与课程完成的证据。

当前 Mac 锁屏，电脑操作工具明确要求用户手动解锁，因此新版本的原生设置界面人工检查与应用内真实网站登录尚未进行。没有绕过锁屏。上一版 Preview 2 的原生启动和学习通登录页显示曾被观察，不能替代新版验收。

## 网页与订阅接入的当前证据

默认模式改为真实网页登录，不要求 API 密钥。四家各有独立网站存储及入口，模型、Chat / Work 和联网模式在网站中选择。生产 `WebAIWorkspace` 在本地真实 WebKit 夹具中完成了两次新会话、发送、完成状态等待及带本题标识的回答读取。该夹具为自建聊天页面，没有真实登录或订阅。

本次另用独立的内置浏览器检查公开站点：ChatGPT 匿名会话的自编 2 + 2 示例实际返回了预期 JSON；DeepSeek 进入登录页；Gemini 显示输入区；豆包显示“该页面暂时不可用”。这个 ChatGPT 示例只证明独立浏览器中的匿名页面可以响应，不证明 HoriStudy 内的账号登录、付费模型或 Work 模式已经可用。

网页自动填写草稿默认关闭。只有用户明确开启、两轮一致、题目和答案格式均通过校验后才允许填写；网页链接未当作已独立验证的检索证据。API 模式仍保留更严格的实际检索引用要求。没有调用任何真实付费 API，没有创建密钥或变更订阅。

## 本次登录修正的复现依据

对上一版提交 `4b91670a3f1ce9c7747ddb6b083d0deeb4a1abb5` 的浏览器代码运行真实 WebKit 夹具：`window.open('about:blank')` 无法保留窗口对象；`WebKitErrorDomain 102` 正常策略取消会被记录成致命页面错误。当前代码修正了这两个可复现缺陷，并增加了生产浏览器控制器测试。

新夹具保留父页面和空白弹窗，跳转至本地登录页后实际以 POST 提交，回调父页面并自动关窗，核对会话 Cookie 存储共享和活动标签页恢复。所用 Cookie 和表单值为自建合成数据，未使用学生账号。正式网页登录可能还存在其他跳转差异，应以本机脱敏诊断和实际账号结果为准。
