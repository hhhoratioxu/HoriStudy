## 网页与订阅接入的当前证据

默认模式改为真实网页登录，不要求 API 密钥。四家各有独立网站存储及入口，模型、Chat / Work 和联网模式在网站中选择。生产 `WebAIWorkspace` 在本地真实 WebKit 夹具中完成了两次新会话、发送、完成状态等待及带本题标识的回答读取。该夹具为自建聊天页面，没有真实登录或订阅。

本次在 HoriStudy 内进行的真实 ChatGPT 检查：

1. 用户在官方登录窗口自行完成账号登录及验证；重启、切换新版后登录仍保留，没有复制其他浏览器的 Cookie。
2. Chat 模式中，点击本软件“测试网页版作答”，用自编 HTTP 404 题执行首轮发送与读回，再自动开启新会话复核。软件显示“网页两轮一致 · 来源待核对”，消息计数增加 2，API 请求为 0。
3. 在网站中明确切换到 Work，重新执行相同示例题。两轮完成并读回，消息计数再增加 2；最终页面的输入区为“使用 ChatGPT Work”。没有使用当前 Codex 聊天作为回答通道。
4. 两个模式均选中“未找到目标资源”，未选择“服务器内部错误”；这是一个标准答案明确的连接样例，不是课程正确率测评。没有核实该账号的订阅档位，也没有测试所有模型、联网检索或长时间 Work 任务。

2026-10-17 的独立浏览器历史观察为：ChatGPT 匿名 2 + 2 示例返回预期 JSON、DeepSeek 要求登录、Gemini 显示输入区、豆包显示“该页面暂时不可用”。它们不能替代本软件中其余服务的账号验收。

网页自动填写草稿默认关闭。只有用户明确开启、两轮一致、题目和答案格式均通过校验后才允许填写；网页链接未当作已独立验证的检索证据。API 模式仍保留更严格的实际检索引用要求。没有调用任何真实付费 API，没有创建密钥或变更订阅。

## Preview 4 的实测修正

- 登录版富文本输入会触发智能引号，导致原提示词读回不一致。现改为转义的纯文本 HTML 插入并逐字验证，未通过时不发送。
- 登录版回答结构与匿名版不同，增加“ChatGPT 说：”语义区域及 `display: contents` 支持；生成完成仍要求本次随机标识、完整 JSON、页面操作状态与稳定读回。
- 回答操作区可能位于正文旁，与输入区共享父容器。只检查当前回答及其后、下一条消息或输入区之前的操作按钮；不借用旧回答的复制按钮。
- 同名、同控件类型、同目标的新对话入口可重复显示；不同对话/任务动作继续暂停，避免猜选。
- 匿名新会话清除确认立即暂停；复核失败保留已读回的首轮未核验草稿；测试失败和取消不会继续显示正在复核。
- 等待提示区分未识别回答、等待完整 JSON、网页仍在生成及缺少完成标记；已发送请求不会自动重发。

## 本次登录修正的复现依据

对上一版提交 `4b91670a3f1ce9c7747ddb6b083d0deeb4a1abb5` 的浏览器代码运行真实 WebKit 夹具：`window.open('about:blank')` 无法保留窗口对象；`WebKitErrorDomain 102` 正常策略取消会被记录成致命页面错误。当前代码修正了这两个可复现缺陷，并增加了生产浏览器控制器测试。

新夹具保留父页面和空白弹窗，跳转至本地登录页后实际以 POST 提交，回调父页面并自动关窗，核对会话 Cookie 存储共享和活动标签页恢复。所用 Cookie 和表单值为自建合成数据，未使用学生账号。正式网页登录可能还存在其他跳转差异，应以本机脱敏诊断和实际账号结果为准。
